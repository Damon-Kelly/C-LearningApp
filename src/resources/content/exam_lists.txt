@q Which expression reads member x through a pointer p to a struct?
@opt p.x
@opt p->x
@opt p::x
@opt p>x
@correct 2
@why The arrow follows the pointer and selects the member. It is short for (*p).x.

@q What does this program print?
@code cpp
struct P { int x; int y; };
P a = {1, 2};
P b = a;
b.x = 9;
cout << a.x << " " << b.x << endl;
@end
@opt 1 9
@opt 9 9
@opt 1 1
@opt 9 1
@correct 1
@why Assigning a struct copies its members. Changing b afterwards does not affect a.

@q What does a nextPtr of nullptr mean in a linked list?
@opt The node is empty
@opt This is the last node
@opt The node was deleted
@opt The list has an error
@correct 2
@why nullptr marks the end of the chain.

@q What does headPtr hold?
@opt The value of the first element
@opt The address of the first node
@opt The number of nodes
@opt The address of the last node
@correct 2
@why The head pointer is the only entry into the list.

@q What does this program print?
@code cpp
struct Node { int data; Node* nextPtr; };
Node* h = nullptr;
for (int v = 1; v <= 3; v++) {
    h = new Node{v, h};
}
cout << h->data << " " << h->nextPtr->data;
@end
@opt 1 2
@opt 3 2
@opt 3 1
@opt 2 1
@correct 2
@why Each new node goes in front, so the head is 3 and the node after it is 2.

@q Why does InsertAtEnd take a Node** ptrToHeadPtr?
@opt To make the function faster
@opt It may have to change the caller's headPtr, for example when the list is empty
@opt Because nodes are stored in pairs
@opt Because Node* cannot be passed to functions
@correct 2
@why A plain Node* would be a copy. The address of the head pointer lets the function change the real one.

@q What does this program print?
@code cpp
struct Node { int data; Node* nextPtr; };
Node c = {5}, b = {7, &c}, a = {9, &b};
int n = 0;
Node* cur = &a;
while (cur != nullptr) {
    n += cur->data; cur = cur->nextPtr;
}
cout << n << endl;
@end
@opt 21
@opt 9
@opt 12
@opt 16
@correct 1
@why The loop visits all three nodes and adds 9 + 7 + 5.

@q What does this program print?
@code cpp
struct Node { int data; Node* nextPtr; };
Node c = {3}, b = {2, &c}, a = {1, &b};
a.nextPtr = b.nextPtr;
int n = 0;
Node* cur = &a;
while (cur) { n++; cur = cur->nextPtr; }
cout << n << endl;
@end
@opt 1
@opt 2
@opt 3
@opt 0
@correct 2
@why a now points straight at c, so b is skipped and the walk visits only a and c.

@q Before deleting the node that curNodePtr points at, what must be done to remove it from the middle of the list?
@opt Link the previous node to the node after it
@opt Set headPtr to nullptr
@opt Copy its data to the head
@opt Nothing, delete is enough
@correct 1
@why Otherwise the list would still point at freed memory. The previous node has to skip over the target.

@q In a loop that frees a list, why is the next pointer saved before delete?
@opt delete clears all pointers
@opt A deleted node's memory cannot be read safely
@opt To keep the node alive
@opt It makes delete faster
@correct 2
@why Reading nextPtr after delete is undefined behaviour.

@q Which statement leaks the nodes of a 3-node list?
@opt FreeList(&headPtr);
@opt headPtr = nullptr;
@opt delete tempPtr;
@opt *ptrToHeadPtr = nullptr; after freeing each node
@correct 2
@why Clearing the head pointer without deleting the nodes leaves them on the heap with nothing pointing at them.

@q What does this program print?
@code cpp
struct Node { int data; Node* nextPtr; };
Node* h = nullptr; int freed = 0;
for (int v = 0; v < 4; v++) h = new Node{v, h};
while (h != nullptr) {
    Node* t = h; h = h->nextPtr;
    delete t; freed++;
}
cout << freed << " " << (h == nullptr) << endl;
@end
@opt 3 1
@opt 4 1
@opt 4 0
@opt 0 1
@correct 2
@why One node is deleted per pass, so freed reaches 4. The loop ends when headPtr is nullptr.

@q What does a function that searches a list return when the list is empty (headPtr is nullptr)?
@opt It crashes
@opt false (not found), because the loop never runs
@opt true
@opt It depends on the value searched for
@correct 2
@why The walking loop's condition is false immediately, so the function reaches its final return false.
